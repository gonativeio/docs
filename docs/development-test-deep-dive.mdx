Building and testing your Median app is the path from configuration to deployment. This section covers how to use Median App Studio, development tools, and platform-specific build and deployment workflows so you can run your app on simulators and devices and publish to the App Store and Google Play.

## What to test

Median apps are composed of web content, native UI elements, and native functionality (such as haptics or biometrics) or SDK integrations from plugins. Test across these areas before release:

### UI & UX

Validate the app interface and user experience across device types, orientations, and OS versions. Typical test cases include navigation, [link handling](https://docs.median.co/docs/link-handling-overview), [deep linking](https://docs.median.co/docs/deep-linking), accessibility, and offline behavior.

### App performance

App performance is strongly correlated to your web experience. Optimize site speed and remediate bottlenecks in JavaScript, images, and embedded functionality. You can also gain performance by using [Native Navigation](https://docs.median.co/docs/native-navigation-overview) instead of web-delivered menus, and by leveraging native SDKs from third-party vendors.

**Performance analysis tools:**

- [SpeedSense](https://www.speedsense.com/)
- [Pingdom](https://tools.pingdom.com/)
- [PageSpeed Insights](https://pagespeed.web.dev/)

For strategies on improving webview app speed, see the [Median blog on speed and performance](https://median.co/blog/how-to-increase-the-speed-and-performance-of-a-webview-app).

### Native device features

Features like [Haptics](https://docs.median.co/docs/haptics), [Biometrics](https://docs.median.co/docs/auth), or [In-App Purchases](https://docs.median.co/docs/iap) require testing on physical devices and cannot be fully simulated in a browser or virtual device.

### Plugin configuration

Validate plugin configuration using [median.dev](https://median.dev) demos or diagnostic tools. Median offers Solution Architecture and Engineering services to advise on plugin implementation. Diagnostic tools can help access log files for troubleshooting with our team or third-party vendors.

## Testing & development tools

### App Studio simulators

Cloud-based virtual devices in [Median App Studio](https://docs.median.co/docs/app-studio) let you quickly test configuration changes in a browser. You can switch between devices, operating systems, and orientations.

<Info>
  **Simulator limitations** Some native device functionality and third-party
  SDKs integrated through plugins cannot be tested in simulators. We highlight
  those cases in the documentation with a warning label.
</Info>

### Browser development tools

Use your browser's dev tools to inspect, debug, and optimize your web experience: viewport, user agent, console, and network requests. See [Development Tools](https://docs.median.co/docs/debug-tools) for details and links to [Chrome DevTools](https://developer.chrome.com/docs/devtools), [Safari Web Development Tools](https://developer.apple.com/safari/tools/), and [Microsoft Edge DevTools](https://learn.microsoft.com/en-us/microsoft-edge/devtools-guide-chromium/landing/).

### Developer demos

[median.dev](https://median.dev) provides demos for JavaScript Bridge functionality and many app features. During development, you can replace the Website URL with a demo page URL on the Overview tab and create a new build. In production, add a link to the demo on your live site—for example, hide it behind a sequence of taps (e.g. searching for specific attributes) so real users don't see it.

<Check>
**Developer Demo**

Display our demo page in your app to test during development [https://median.dev/share-function](https://median.dev/share-function)

</Check>

If a demo works in your app but your own site does not: debug your page in the app using [Development Tools](https://docs.median.co/docs/debug-tools), inspect the demo source in your desktop browser, and recheck your JavaScript against the documentation.

### Physical device testing

Physical devices are the gold standard for testing native functionality and end-to-end flows. Distribute to devices via [Upload iOS to TestFlight](https://docs.median.co/docs/upload-ios-to-testflight) or [Install Android APK](https://docs.median.co/docs/install-android-apk).

When performing QA, you may need to uninstall older test versions:

- **Android:** [Delete, disable & manage unused apps](https://support.google.com/googleplay/topic/13627086)
- **iOS:** [Remove or delete apps from iPhone](https://support.apple.com/en-ca/guide/iphone/iph248b543ca/ios)

### `adb` and `sysdiagnose`

For in-depth logs, system information, and application metrics, use platform diagnostic tools: [Android Debug Bridge (adb)](https://developer.android.com/tools/adb) and [Sysdiagnose](https://it-training.apple.com/tutorials/support/sup075/). See [Development Tools](https://docs.median.co/docs/debug-tools) for more on debugging in the app.

  <Accordion title="App Studio simulators" icon="mobile-screen">
    - **UI / UX:** Switch between devices, OS versions, and orientations.
    - **Performance:** No detailed logs.
    - **Native features:** Simulators don't fully support native features.
    - **Plugin config:** Shows high-level information only.
  </Accordion>

<Accordion title="Browser DevTools" icon="window-maximize">
  - **UI / UX:** Limited to changing the user agent and viewport. -
  **Performance:** Best for analyzing web assets. - **Native features:** Native
  features can't be tested in a browser. - **Plugin config:** Console output
  only.
</Accordion>

<Accordion title="Appetize debug mode" icon="bug">
  - **UI / UX:** Switch between devices, OS versions, and orientations. -
  **Performance:** Network logs are available. - **Native features:** Simulators
  don't fully support native features. - **Plugin config:** Device logs help
  validate plugin behavior.
</Accordion>

<Accordion title="Physical device" icon="mobile">
  - **UI / UX and performance:** Coverage depends on maintaining a suite of test
  devices. - **Native features:** Required to test native features. - **Plugin
  config:** The fastest way to validate plugins.
</Accordion>

  <Accordion title="adb and sysdiagnose" icon="terminal">
    - **UI / UX:** Not suited to visual testing.
    - **Performance:** Detailed metrics and performance analysis.
    - **Native features:** Logs and error codes.
    - **Plugin config:** Best for diagnosing SDK issues and sharing logs with vendors.
  </Accordion>
</AccordionGroup>
## Summary

Use **Median App Studio** to configure and preview your app, **Development Tools** and median.dev to debug and test behavior, and **iOS Build & Deployment** and **Android Build & Deployment** to produce installable builds and publish to the stores. **App Configuration & Management** covers identifiers, config, and CI/CD so your build pipeline stays consistent.
